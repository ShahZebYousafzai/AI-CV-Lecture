## Note on the box-and-arrow / state diagrams in the notebooks

Every architecture diagram, state-flow diagram, and graph-topology diagram in both notebooks
(the supervisor/worker diagram, the LangGraph state-machine diagrams, the human-in-the-loop
interrupt/resume diagram, the agentic RAG decision-flow diagram, etc.) is drawn **natively in
code** — either with `graphviz` (rendered to PNG at build time) or with LangGraph's own
built-in `get_graph().draw_mermaid_png()` renderer, which draws the *actual* graph object that
was just built and executed in that cell. These are not illustrations and nothing was
generated by an image model; they are exact, editable, reproducible renderings of the graphs
defined in the code immediately above them, in the same convention used for the native
PowerPoint shapes in the Session 34 decks.

## Why these papers

The user's spec for the Agentic RAG notebook asks for an agent that decides whether
retrieval is necessary, evaluates retrieved results, and rewrites the query and retries when
results are insufficient. That is not a generic RAG pattern — it is, specifically, the
research lineage of Self-RAG (on-demand retrieval + self-critique), CRAG (a retrieval
evaluator with Correct/Ambiguous/Incorrect grading and corrective actions), and Adaptive-RAG
(routing by query complexity, including a retry loop). The notebook's LangGraph implementation
is a simplified, fully local teaching version of the pattern these three papers define, so
citing them is citing the actual source of the design rather than a decorative reference.
AutoGen is the paper that popularised multi-agent LLM conversations (joint chat, hierarchical
chat, human-in-the-loop chat) that the LangGraph-II notebook's supervisor/worker graph and
approval step are a hands-on implementation of.
